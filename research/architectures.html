الـ 3 archs النهائيين

F1

Data-centric encoder

simplest strong system
normalize -> MARBERTv2 token head 5 classes {EGY, GLF, MSA, SHARED, OTHER} -> temperature scaling -> decision layer (target) -> lexicon suggestion -> JSON (ONNX int8)

PROS

  • أبسط حل وأسرع
  • كل الجودة جاية من الداتا (D1–D3)

CONS

  • بيبدأ من الصفر في التمييز بين MSA واللهجة
F2

Warm-start + multi-task encoder

recommended ship targetrecommended
init from ALDi-Token-DI (MARBERT, already MSA/DA-aware) -> token head 5 classes (+ marker-lexicon feature) -> aux heads: sentence ALDi (distilled), sentence DID -> calibration -> decision layer -> JSON (ONNX int8)

PROS

  • بيورث المعرفة من الداتا الحقيقية بتاعة CALCS (حوالي 20 ألف token) اللي معرفناش ننزّلها
  • نفس سرعة F1
  • الـ aux heads بتساعد في الكلمات المشتركة

CONS

  • تدريب أعقد شوية
  • لازم نتأكد إنه ميرجعش لعادة "تجاهل الكلمة الغريبة"
F3

F2 + System-2 re-check

batch / post-call mode
F2 labels all words (one pass) if conf(w) < tau: AGS-style focused model: "[TGT] w [TGT]" in context or local LLM (ALLaM-7B / Fanar-9B) per word merge -> decision layer -> JSON

PROS

  • أعلى جودة في الحالات الصعبة
  • tau بيتحكم في التوازن بين الجودة والـ latency
  • أقوى production story

CONS

  • مكوّنات أكتر نبنيها
  • مش مناسب للـ guard الـ real-time قبل الـ TTS

الترشيح بعد البحث

نسلّم F2 كـ System 1، ونقارنه بـ F1 كـ ablation، وده بيبيّن قيمة الـ warm start بالأرقام. وF3 يبقى flag اختياري في وضع الـ batch. وفي الـ README نعرض جدول: morphology rule، وبعده lexicon، وبعده ALDi-Token-DI كما هو، وبعده F1، وبعده F2، وبعده F3، على نفس الـ gold set.

الملاحظة اللي بتحكم كل القرارات

المشكلة token-level: قرار لكل كلمة، والقرار بيعتمد على السياق. فالسؤال الأهم في أي arch: كام forward pass محتاجين للجملة؟ الـ encoder بيعمل pass واحد لكل الكلمات. أي موديل "sentence-level" هيحتاج pass لكل كلمة، والـ latency هتتضرب في عدد الكلمات.

الموديل يتنبّأ باللهجة، والقرار ييجي بعده

الموديل يطلع لكل كلمة توزيع على {EGY, GLF, MSA, SHARED, OTHER}، وبعدين decision layer بسيطة تقارنه بالـ target. كده موديل واحد يخدم أي target، والـ label الإضافي (Nice-to-have) ييجي لوحده.

System One models — the ones you sent

الـ System One models: إيه هي، وتنفع هنا ولا لأ

دي عيلة جديدة ظهرت في سبتمبر 2026: موديلات بتاخد state (نص) وtyped questions (Noul = yes/no، أو Choice، أو Score)، وترجع احتمالات calibrated في pass واحد من غير ما تولّد نص. فكرتها هي نفس فكرتك بالظبط: decision maker أسرع من الـ LLM. بس اتصممت عشان قرار واحد على النص كله، مش قرار لكل كلمة.

StrandsAgents/strands-decider-2B-hobson-v19
  • LoRA على Qwen3.5-2B-Base، وفوقه pointer head (حوالي مليون parameter) بيقارن الـ hidden state عند <answer> بآخر token في كل option.
  • median 115 ms على RTX 3090 لكل request.
  • متدرّب على datasets إنجليزي بس، ومفيش أي claim عن العربي.
  • إعادة التدريب بالـ recipe بتاعته: حوالي 11 ساعة على 3090.
ينفع كـ System 2 judge على الكلمات اللي مش واضحة، أو كـ gate على مستوى الجملة. مش هينفع System 1 على مستوى الكلمة.
Contrastive-LM/CLM-v0.1-8B
  • Qwen3-8B frozen، وفوقه 2 projection heads (state وaction)، متدرّبين بـ InfoNCE.
  • الـ embedding بييجي من آخر token (last-token pooling)، يعني متجه واحد للنص كله.
  • الـ fine-tuning رخيص لأن الـ heads بس اللي بتتدرّب. والـ action caching بيفيد لو عندك options كتير.
  • الـ model card مكتوب فيه language: en.
عشان يدّي label لكل كلمة لازم نعمل pass لموديل 8B على كل كلمة. والـ caching مش هيفيد، لأن عندنا 4–5 labels بس. فهو غير مناسب للمشكلة دي.
autotrust/JEV-9B · JEV-27B (open students of TypeSafe Jev)
  • System 1 adapter (40M parameter) على Qwen3.5-9B، وSystem 2 (توليد عادي) في نفس الـ weights.
  • حوالي 90 ms لكل decision على B200، و2.5 ms لكل decision لو batch من 128.
  • Choice بيقبل من 2 لـ 16 option. ومتدرّب distillation من Jev، وكله إنجليزي.
الفكرة اللي تستاهل ناخدها منه هي Blocks of Experts: backbone frozen وفوقه block صغير متدرّب. ودي نفس فكرة Arch F عندنا.

الخلاصة عن الـ System One models

الـ System One models نموذج تفكير صح، والـ token classifier هو أنقى شكل لـ System 1 على مستوى الكلمة: pass واحد، وdistribution calibrated لكل كلمة. فهناخد من عيلة Jev الفلسفة (calibrated typed decisions، والـ System 1/2 routing، والـ frozen backbone مع head صغير)، ونطبّقها على encoder أو decoder بيعمل labeling لكل الكلمات مرة واحدة. والـ decider الجاهز ممكن يدخل كـ System 2 بس على الكلمات القليلة اللي مش واضحة، ولازم نقيسه على عربي الأول.

ليه ده

  • Latency: أغلب الكلمات بتعدّي من pass واحد لـ encoder (ملي ثواني قليلة على GPU)، والـ LLM بيشتغل بس على الكلمات الصعبة.
  • Quality: الحالات النادرة اللي محتاجة فهم أعمق بتروح للموديل الأكبر.
  • Productisation: لو الـ resources زادت نكبّر System 2 أو نزوّد الـ threshold، ونفس الـ arch يكمّل. وده بالظبط معيار "Same solution if more resources".
  • Calibration: الـ confidence اللي في الـ output بيبقى معناه حقيقي، لأننا بنعمله temperature scaling على الـ dev set.

المخاطر وإزاي نقللها

  • الداتا: مفيش dataset فيها labels على مستوى الكلمة لمصري وخليجي وMSA. الحل: synthetic injection من MADAR lexicon، ونضيف عليها labels من teacher LLM.
  • Eval منفوخ: الـ gold set لازم يبقى جمل حقيقية يحيى يعلّمها بإيده، وتكون منفصلة تماماً عن الـ synthetic.
  • الـ compute: الـ GPU المحلي 3.68 GiB بس. الـ encoder يتدرّب عليه عادي، بس الـ 7B teacher محتاج Kaggle/Colab، أو compute credits من Tuner، وهما عرضوا ده.
  • الوقت: System 2 يبقى optional flag. لو الوقت ضاق، نسلّم C لوحده، ونكتب الـ cascade كـ production plan.
Data strategy

الداتا: أهم من الموديل

1 · Synthetic injection

ناخد جمل مصري حقيقية، ونبدّل كلمات فيها بالمقابل الخليجي أو الـ MSA من MADAR lexicon (1,045 concept × 25 مدينة) أو من الـ parallel corpora (مصري↔MSA). الـ labels بتطلع دقيقة 100% ومن غير تكلفة، وبتحاكي بالظبط "LLM بيخلط اللهجات".

2 · Teacher labels

LLM عربي local (Falcon-H1-Arabic أو ALLaM أو Qwen) يعلّم كلمات في جمل حقيقية، مصري وخليجي وMSA، من FineWeb2-arz وGumar وغيرهم. ده مسموح لأن القيد على الـ inference بس، وبنكتب ده صريح في الـ README.

3 · Real word-level labels

LinCE MSA-EA: tweets متعلّمة على مستوى الكلمة (MSA / EA / NE / ambiguous)، حوالي 20 ألف token في الـ dev. مفيدة كـ training إضافي، وكـ external eval لزوج MSA-مصري.

4 · Gold eval set (يدوي)

من 200 لـ 300 جملة يحيى يعلّمها بإيده. فيها جمل من output بتاع LLM فيه خلط حقيقي، ومعاها annotation guideline مكتوبة. الـ P/R/F1 بتتحسب على الكلمات اللي بتـ deviate، ومعاها per-label breakdown.
