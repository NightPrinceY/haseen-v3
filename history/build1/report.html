HaSeen

هـ · سين

I built HaSeen to read an Arabic sentence and say, for every word, whether it belongs to the target variety (Egyptian, Gulf or MSA) and what it is when it does not. It runs offline, needs no LLM, and takes about 11 ms on a CPU. The name is the idea: Egyptian says هيتم and MSA says سيتم, so one letter decides the dialect.

This page is the whole story, from reading the task to the shipped model. Each ↗ tag next to a number links to the file in the repo where that number lives.

01 · The task
What Tuner asked, and what I decided

  
Given text and a target dialect, label every word as conforming or deviating, and name what a deviating word is instead. No cloud LLM at inference. The answers below decided the scope.

  

    
My questionTuner's answerWhat I did

    
      
Is a word valid in both the target and MSA conforming?YesEach word gets three bits: is it natural in Egyptian? in Gulf? in MSA? It deviates only when the target's bit is 0. الاجتماع conforms everywhere.

      
Does morphology count? (prefixes like هـ، حـ، بـ and the negation ما…ش)Your callOnly positive evidence: سـ+verb and سوف deviate in Egyptian. A word that merely lacks هـ (أتأخر) conforms, as in the task's own example.

      
CPU or GPU? Self-hosted model OK?GPU, yesI still made it run on CPU (int8 ONNX, 11 ms), because a guard that sits before the TTS on every turn has to be cheap.

      
Arabizi / code-switching?Your callLatin script, digits and names always conform and are not scored. Arabizi is future work.

      
LLMs to build data offline?Your callYes, at development time only, and checked by a native speaker. Gold candidates came from 5 open LLM families; training labels came from rules, a lexicon and corpus evidence (below).

    

  
Answers clarifications.md · targets I fixed before any work (F1 ≥ 0.85, p95 < 20 ms CPU) PRD.md

  

    
Egyptian
Primary target. The register is Egyptian customer-service speech, which is semi-formal: هل، تم، يمكنك are natural there. I checked this with a native speaker (42 yes/no questions). questions_for_yahya.md

    
MSA
Supported. Dialect words inside formal text deviate.

    
Gulf
Experimental and strict. I have no native Gulf annotator, so I say so instead of overclaiming.

  







  
02 · Research
What the field already knew

  
Before choosing anything I read the papers, listed every dataset with its licence, and spent about $0.03 on two small spikes to check what really exists. Six findings shaped everything after.

  

    
LLMs drift out of dialect
In the AMIYA shared task, a baseline LLM answered in Egyptian only 11.1% of the time when asked to. Sentence-level scores can't say which word broke the dialect; a word-level detector can. R2-R3

    
Word lists are not enough
Published Gulf cue lists had precision 0.0 on multi-dialect data, and 56% of dialect sentences are valid in several regions. Context has to decide. R1-papers

    
No word-level data to download
LinCE MSA–Egyptian, the obvious dataset, is offline. MADAR has 11,600 parallel sentences (Cairo / Doha / MSA). So I had to build labelled data myself. spike

    
Morphology alone fails
"Deviating if the Egyptian analyzer can't parse it" scored F1 0.16: the CAMeL Egyptian database analyzes 99% of MSA words. Rules became evidence for labels, not the decider. spike

    
A good warm start exists
VARabi/ALDi-Token-DI already tags MSA vs dialect per token, but it misses a single سوف inside Egyptian. My data had to teach single-word slips. R4

    
MARBERT tokenizes dialect best
On 30k Egyptian words: 1.86 subwords per word and 2.3% unknown, against 17% for other Arabic BERTs before normalization. spike 3

  







  
03 · Architecture
Nine options, one rule written in advance

  
I scored nine designs on quality, latency, effort, productisation and risk, kept three finalists, and wrote the rule for choosing between them before training anything. Tap a card to see what happened to that option.

  

  
Decision rule (written 12 Oct, before the pilot)
Ship A (encoder) if gold F1 ≥ 0.85 and latency is fine. Try B (decoder backbone) once, only if A's errors come from missing knowledge. Ship C (cascade) only if B beats A by ≥ 3 F1. A reached 0.963, so B and C were not needed. architectures.html PRD §12

The model barely mattered, the labels did

  
Six small runs on an L4 (about $0.95) compared backbones, warm starts and heads, and then two ways of labelling the same data. The check set was 30 realistic service sentences.

What I learned
Changing only how "shared" words were labelled lifted realistic F1 from 0.627 to 0.800. All backbones and heads were within about 1 F1 of each other. So I put the effort into data, not into a bigger model. PILOT_REPORT.md

    
Choice
ALDi-Token-DI warm start + pointer head (best calibration), with the linear head kept as the control. Pilot code and raw results research/pilot

  







  
05 · Benchmark
A gold set built first, then frozen

  
I built the evaluation set before the training data, from a different source, and froze it with sha256 hashes. It was never used for training, tuning or picking a model.

  

    
1 · Real agent output
560 replies from 5 open LLM families (Gemma-4-31B, Llama-3.3-70B, DeepSeek-V4-Flash, Aya-Expanse-32B, Llama-4-Scout) in 4 prompt styles, because LLM replies are where the slips happen. 38 corrupted generations were removed. gen_router.py raw

    
2 · Rules, then labels
Guideline v1.2 with 40 anchor sentences. Claude labelled every token; a native speaker settled the register in 42 yes/no checks. GUIDELINE.md anchors

    
3 · Second opinion
A DeepSeek-V4-Pro committee agreed on 97.7% of tokens, but κ was only 0.21: it flags normal service words as MSA. I recorded it and did not use it as truth. disagreements

06 · Training data
92k sentences without an LLM API

  
Instead of asking an LLM to label (the research says the teacher can be worse than the student), I used real text and parallel corpora, and wrote a labeler that gives each word three bits and says "unknown" when it is not sure. Unknown bits carry no loss.

  
  

    
Sources
Dial2MSA, oasst2 Egyptian/MSA, Arabic STS, Nile-Chat, MADAR-6, Saudi customer-service chats, Najdi conversations, and the Lahga dictionary (25k forms). Each one with its licence. DATA_STUDY.md

    
Alignment
158k dialect↔MSA pairs aligned word by word on an L4 (MARBERTv2 layer 8, about $0.12). A word is swapped only when both of its neighbours match. align_remote.py build_dataset.py

    
Labeler
Core lexicon (≈270 entries, 20 context rules for homographs), morphology, corpus counts and gates. I audited every flagged word type across about 800k tokens in 3 rounds and fixed about 25 false-positive patterns. labeler.py core_v2.tsv

    
No leakage
0 shared 8-grams between any source and the gold set (7,933 gold 8-grams). DATA_PLAN.md

    
Native check
A native speaker accepted 100 of 100 sampled training sentences. g3_check_v1.md answers

    
Generalization test
148 Gulf word forms are held out of training completely, to test words the model has never seen. heldout_forms

  

  
Splits: train 92,285 sentences (961,859 words) · dev 6,902 · held-out 4,298. On HF as HaSeen-Mix-92K and HaSeen-Service-Triples (197 hand-written turns × 3 varieties templates.tsv).

How the shipped model was chosen
The rule, fixed before the runs: among the final three seeds, ship the one with the highest dev score. That is R5v6-pointer-s42 (dev 0.9857). Its gold scores are a little below the seed average on Egyptian (0.963 vs 0.966), and I kept it anyway, because picking by gold would leak the benchmark. RESULTS.md

  
Each run trains for about 22 minutes on one L4. All GPU work, from the spikes to the last run, cost about $4 of HF sandbox time. compute-budget.md experiments/

One install, one command

    
I packaged HaSeen as a small SDK. The default install is CPU-only (onnxruntime + tokenizers, no PyTorch). The first run downloads the public model once; after that it works offline.


uv tool install git+https://github.com/NightPrinceY/haseen     # or pipx install …
haseen "أنا أبغى أروح الاجتماع بكرة بس سوف أتأخر شوية" -t egy

HaSeen · target Egyptian · 2 of 9 words deviate · 6.4 ms
  أبغى  Gulf   0.998
  سوف   MSA    0.999   → هـ + الفعل


import haseen
haseen.detect("الفني سيصل لحضرتك الساعة اتنين", "egy")["deviations"]   # ['سيصل']

haseen serve --port 8000        # POST /detect {"text": "…", "target": "egy"}  ·  GET /health
cat replies.txt | haseen -t egy # one sentence per line → JSON lines (post-call audits)


docker run --rm -p 8000:8000 nightprincey/haseen    # the server: model inside, offline, non-root, health-checked

    
api.py cli.py server.py engine.py Dockerfile Docker Hub

  

  

    
Tested like a stranger
Fresh environment, no Hugging Face account: the model downloaded in 55 s, then ran with the network off. The Docker image runs with --network none. RESULTS.md

    
Same decisions
The package engine matches the original ONNX script on all 794 benchmark sentences (0 differences), at 7.9 ms p50 on my laptop CPU. On the benchmark: Egyptian 0.965, MSA 0.710, Gulf 0.773 (int8 costs strict Gulf 3 points).

    
Browser demo
The same int8 model runs inside the page with onnxruntime-web. Its JS tokenizer matches Python on 795/795 benchmark sentences. demo/web

  







  
10 · Limits & next
What V1 does not do yet

  

    
Known gaps
    
      
  • MSA target over-flags some service nouns (F1 0.704).
    • 
      
  • Gulf is strict and not checked by a native speaker (F1 0.804).
    • 
      
  • Rare ث-spellings such as أبعثلك are missed; "من حقك" is sometimes flagged.
    • 
      
  • Suggestions come from a dictionary and can be off: for الحين it suggests بقا, where an Egyptian agent says دلوقتي. أبغى → عايز is not suggested yet.
    • 
      
  • Levantine and Maghrebi come back as "unknown", not as named dialects.
    • 
      
  • MADAR and Dial2MSA are research-only licences, so V1 is for research use.
    • 
    

    
Next
    
      
  • V1.1: a curated suggestion table for the core markers; more ث-spelling transforms; Egyptian حقك contexts.
    • 
      
  • Production data: the same pipeline rebuilt on ODC-BY / MIT sources and Tuner's own call transcripts.
    • 
      
  • Gulf: a native Gulf annotator for a real gold set.
    • 
      
  • System 2: a local LLM re-check for low-confidence words, in batch mode (finalist C), if errors call for it.
    • 
      
  • STT: run on ASR transcripts to watch dialect drift in the voice pipeline itself.
